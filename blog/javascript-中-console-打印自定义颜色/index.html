JavaScript 中 console 打印自定义颜色

发布于 2026-02-06 09:42:32 · 2 分钟 · 标签： JavaScript

我们在写 CLI、调日志、写脚手架时，彩色输出几乎是刚需。今天我就系统聊聊 JavaScript 在控制台输出颜色这件事，内容从底层原理讲到库的使用，再到实战建议，尽量做到“看完就能用”。

1. 为什么需要彩色控制台输出？

如果你和我一样，写过 CLI 或 Node 服务日志，就会知道：

  • 错误一片红，一眼就能定位
  • 警告是黄色，不至于忽略
  • 成功是绿色，仪式感拉满
  • 信息是蓝色，层次更清晰

简而言之：提升可读性 + 降低噪音。

2. 基础原理：ANSI Escape Codes

绝大多数终端都支持 ANSI 转义序列，它就是彩色输出的底层核心。

最常见的格式如下：

\033[31m红色文字\033[0m

含义：

  • ​\033[​：转义序列开始
  • ​31m​：设置前景色为红色
  • ​0m​：重置颜色和样式（必须有！）

常用颜色码

颜色前景色代码
黑30
红31
绿32
黄33
蓝34
紫35
青36
白37
重置0

3. JavaScript 原生输出颜色

在 Node.js 控制台里可以直接打印 ANSI：

console.log("\033[32mSuccess!\033[0m");
console.log("\033[31mError!\033[0m");

如果你想粗体、下划线，也可以加样式：

console.log("\033[1;34mBold Blue\033[0m");

但缺点也很明显：可读性差、难维护。

4. 实用库推荐（更舒服的写法）

我日常最常用的两个库：

✅ chalk（明星库）

npm i chalk
import chalk from "chalk";

console.log(chalk.green("Success"));
console.log(chalk.red.bold("Error"));

优点：

  • API 清晰
  • 支持链式
  • 支持 true color

✅ kleur（轻量替代）

npm i kleur
import { green, red, bold } from "kleur";

console.log(green("OK"));
console.log(bold().red("Failed"));

优点：

  • 体积小
  • 速度快
  • 没有大依赖

5. 高级玩法：24-bit 真彩色

如果你的终端支持真彩色（大多数现代终端都支持）：

console.log("\033[38;2;255;100;0mOrange Text\033[0m");

格式：

\033[38;2;R;G;Bm

背景色用 48;2​。

6. 兼容性与配置建议

1) 检测终端是否支持颜色

常见判断：

process.stdout.isTTY

2) 支持关闭颜色

CLI 常见做法：

  • ​--no-color​ 参数
  • 或尊重 NO_COLOR​ 环境变量

3) Windows 兼容性

旧版 Windows CMD 不支持 ANSI，但现在的 Windows Terminal / PowerShell / WSL 已经没太大问题。

7. 我个人的一套颜色风格约定

如果你也在写 CLI 或日志系统，可以参考：

  • ✅ Success：绿色
  • ⚠️ Warning：黄色
  • ❌ Error：红色
  • ℹ️ Info：蓝色
  • 🐛 Debug：灰色

保持统一很重要。

8. 最佳实践小结

✅ 不要忘 reset 每次加颜色一定要 \033[0m​ 或使用库自动重置。

✅ 少即是多 颜色不要滥用，重点突出即可。

✅ 对用户友好 允许用户关闭颜色输出，尤其是在写文件或日志系统时。

写在最后

彩色控制台输出虽然是“小事”，但它能显著提升一个 CLI 工具的体验感。只要掌握 ANSI 规则，再配合合适的库，写出来的命令行工具立刻“高级感拉满”。
