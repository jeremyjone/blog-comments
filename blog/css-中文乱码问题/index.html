CSS 中文乱码问题

发布于 2026-01-14 09:20:19 · 4 分钟 · 标签： css

CSS content​ 中文乱码问题：从 Nginx 配置到 PostCSS 编译的完整解决方案

一、问题起因

1.1 现象描述

线上部署的 Vue 项目，在部分用户电脑上出现诡异现象：

  • 页面主体内容正常显示
  • 只有通过 CSS ::before​ / ::after​ 的 content​ 属性显示的中文变成乱码
  • 表现为类似 æš‚æ— ç›¸å…³æ•°æ®​ 这样的”拉丁字符乱码串”

典型代码：

.my-empty {
  &::after {
    content: "暂无相关数据";
    color: #999;
  }
}

1.2 问题特征

  • 同一环境、不同电脑表现不同：有的人正常，有的人乱码
  • 不是字体缺失：字体缺失会显示”豆腐块（□）“，而这里是拉丁字符乱码
  • 只影响 CSS ​content​​：HTML 中的中文正常

1.3 根本原因

浏览器在解析 CSS 文件时，使用了错误的字符集（charset） 。

具体链路：

  1. CSS 源文件是 UTF-8 编码
  2. 构建打包后，CSS 产物仍是 UTF-8
  3. 服务器返回 CSS 时，Content-Type​ 响应头没有声明 ​charset=utf-8​​
  4. 部分浏览器/代理环境会按默认编码（如 ISO-8859-1、GBK）解读 CSS
  5. UTF-8 的中文字节被按错误编码解码，变成乱码

二、问题排查

2.1 判断是”字体问题”还是”编码问题”

表现原因
方块/豆腐块（□□□）字体缺失
拉丁乱码（æš‚æ— …）编码错误

2.2 用 DevTools 验证

  1. 打开出问题的页面

  2. DevTools → Network → 找到加载的 .css​ 文件

  3. 查看 Response Headers：

    Content-Type: text/css

如果只有 text/css​，没有 charset=utf-8​，就是问题所在。

正确的响应头应该是：

Content-Type: text/css; charset=utf-8

三、解决方案一：Nginx 强制 UTF-8（推荐）

3.1 原理

在服务端（Nginx）层面，强制所有 CSS 响应都带上 charset=utf-8​，让浏览器明确知道”用 UTF-8 解码”。

3.2 配置方法

在 nginx.conf 的 http {}​ 块中添加：

http {
  include       mime.types;
  default_type  application/octet-stream;

  # 强制输出使用 UTF-8
  charset utf-8;
  charset_types text/css;

  # ...其他配置...
}

配置说明：

指令作用
​charset utf-8;​在响应头中添加 charset=utf-8​
​charset_types text/css;​指定哪些 MIME 类型需要附加 charset（默认只对 text/html​ 生效）

3.3 如果使用了 sub_filter​

当你的场景涉及多入口部署、路径替换（例如把 /web/​ 替换为 /sub/web/​），启用 sub_filter​ 后更容易触发此问题：

location /sub/web/ {
  alias /usr/share/nginx/html/;
  index partner-list.html;

  sub_filter '/web/' '/sub/web/';
  sub_filter_once off;
  sub_filter_types text/css application/javascript;

  # 确保 charset 生效
  charset utf-8;
}

3.4 验证

部署后用 curl 检查：

curl -I http://your-host/static/css/app.xxx.css

响应头应包含：

Content-Type: text/css; charset=utf-8

四、解决方案二：Unicode 转义（前端编译时处理）

4.1 原理

将 CSS 中的中文字符转换为 Unicode 转义序列，这样即使浏览器按错误编码解读 CSS，也不会影响 content​ 的显示。

转换示例：

原始写法Unicode 转义写法
​content: "暂无相关数据";​​content: "\6682\65e0\76f8\5173\6570\636e";​

4.2 方法一：手动硬写

直接在 CSS/Less/Scss 中写 Unicode 转义：

.my-empty {
  &::after {
    content: "\6682\65e0\76f8\5173\6570\636e"; /* 暂无相关数据 */
    color: #999;
  }
}

转换工具（JavaScript）：

function toUnicodeEscape(str) {
  return str.split('').map(char => {
    const code = char.charCodeAt(0);
    if (code > 127) {
      return '\\' + code.toString(16).padStart(4, '0');
    }
    return char;
  }).join('');
}

console.log(toUnicodeEscape('暂无相关数据'));
// 输出: \6682\65e0\76f8\5173\6570\636e

4.3 方法二：PostCSS 插件自动转换（推荐）

通过 PostCSS 插件，在构建时自动将 content​ 中的中文转为 Unicode 转义。

安装：

npm install postcss-content-unicode --save-dev

如果没有现成插件，可以自己写一个简单的：

module.exports = () => {
  return {
    postcssPlugin: 'postcss-content-unicode',
    Declaration(decl) {
      if (decl.prop === 'content' && decl.value) {
        decl.value = decl.value.replace(/[\u4e00-\u9fa5]/g, (char) => {
          return '\\' + char.charCodeAt(0).toString(16);
        });
      }
    }
  };
};
module.exports.postcss = true;

在 Vue CLI 项目中使用：

module.exports = {
  plugins: [
    require('autoprefixer'),
    require('./postcss-plugins/postcss-content-unicode.js')
  ]
};

或在 vue.config.js 中配置：

module.exports = {
  css: {
    loaderOptions: {
      postcss: {
        postcssOptions: {
          plugins: [
            require('./postcss-plugins/postcss-content-unicode.js')()
          ]
        }
      }
    }
  }
};

4.4 两种方案对比

维度Nginx 方案Unicode 转义方案
改动位置服务端配置前端源码/构建配置
生效范围全局，所有 CSS仅 content​ 属性
维护成本一次配置，永久生效手动写需每次转换；PostCSS 需维护插件
适用场景有服务端控制权无服务端控制权、CDN 托管
可靠性根治（明确声明编码）规避（绕过编码问题）

五、最佳实践

5.1 推荐组合

  1. 优先使用 Nginx 方案：从根本上解决编码声明问题
  2. PostCSS 作为双保险：即使服务端配置有遗漏，也能兜底

5.2 检查清单

  • 源码文件编码为 UTF-8（VS Code 右下角确认）
  • Nginx 配置 charset utf-8;​ + charset_types text/css;​
  • 如果用了 sub_filter​，确保 sub_filter_types​ 包含 text/css​
  • 验证 CSS 响应头包含 charset=utf-8​

六、总结

CSS content​ 中文乱码问题，表面是”样式显示异常”，实际是HTTP 响应头编码声明缺失导致的字符集解码错误。

问题层面解决方案
服务端Nginx charset utf-8; charset_types text/css;​
前端构建PostCSS 插件自动转 Unicode 转义
临时应急手动将中文改为 \xxxx​ 格式

在现代 Web 开发中，保证源码 UTF-8 + 服务端响应头声明 UTF-8，是避免此类问题的根本之道。
